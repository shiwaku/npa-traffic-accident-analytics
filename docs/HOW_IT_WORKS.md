# 仕組み

いま動いているものが、何をどう処理しているか。
設計の経緯と採らなかった案は [DESIGN.md](DESIGN.md) にある。

---

## 1. 全体像

登場するのは4つだけ。

```
① claude.ai / Claude Code        利用者が日本語で聞く。対話はここが担う
        │  MCP（HTTPS）
        ▼
② MCPサーバー  mcp_server/server.py     質問の条件 → SQL に組み立てる
        │  DuckDB + httpfs
        ▼
③ Cloudflare R2   honhyo_2019-2024.parquet   96.6MB。必要な列だけ渡す
        │
        ▼
④ 集計結果 → ① に返り、Claude が日本語で説明する
```

**対話しているのは①であって、こちらのサーバーではない。**
②は「この条件で集計して」と言われたら数字を返すだけの部品で、会話の文脈も
言葉の解釈も持っていない。ここを取り違えると全体が分からなくなる。

---

## 2. 質問1つで何が起きるか

「生活道路の若年層の事故の推移は？」と入力したときの流れ。

**1. 利用者のClaudeが質問を読む**

コネクタを登録した時点で、Claude はサーバーの `instructions`（定義6項目）と
ツールの説明文を受け取っている。そこに「生活道路は strict と broad で件数が
約2倍変わる」「年齢は0〜24歳が最小区分」と書いてあるので、曖昧なら聞き返す。

**2. ツールを呼ぶ**

Claude が `aggregate` を呼ぶ。引数はこうなる。

```json
{
  "group_by": ["year"],
  "seikatsu": "strict",
  "party_age": ["01"],
  "party_type": ["61", "51", "52"],
  "party_scope": "either"
}
```

**ラベル文字列ではなくコード値**を渡す。理由は 4-1 に書く。

**3. サーバーがSQLを組み立てる**

コード値をラベルに変換し、WHERE 句を作る。

```sql
SELECT "資料年次" AS 年, count(*) AS 件数, ...
FROM honhyo
WHERE "車道幅員" IN ('単路－3.5m未満','単路－3.5m以上','交差点－小（5.5m未満）－小')
  AND (("年齢（当事者A）" IN ('0～24歳') AND "当事者種別（当事者A）" IN ('歩行者','軽車両－自転車','軽車両－駆動補助機付自転車'))
    OR ("年齢（当事者B）" IN ('0～24歳') AND "当事者種別（当事者B）" IN ('歩行者','軽車両－自転車','軽車両－駆動補助機付自転車')))
GROUP BY 1 ORDER BY 1 LIMIT 200
```

**4. DuckDB が R2 を読む**

`httpfs` 拡張が HTTP Range リクエストで Parquet の必要な部分だけ取る。
96.6MB のうち転送されるのは**約4MB**。年を絞れば0.84MBまで下がる。

Parquet は列指向なので、読まない列は転送されない。座標系の列が全体の73%を
占めるが、集計では触らないので無関係。

**5. 結果を返す**

行データに加えて、**実行したSQL**と**注意事項**を返す。

```json
{
  "rows": [{"年": 2019, "件数": 10335, ...}, ...],
  "notes": [
    "生活道路 = 車道幅員5.5m未満。strict(交差する両方が5.5m未満)で絞った。broad にすると件数は約2倍になる",
    "年齢 0〜24歳 は年齢層コードの最小区分。10代のみの切り出しは不可能",
    "当事者AまたはBが条件を満たす事故を行単位で1件と数えた(二重計上なし)"
  ],
  "sql": "SELECT ..."
}
```

`notes` は Claude が利用者に伝えるための材料。どの定義を使ったかを黙って
済ませないための仕掛けでもある。

**6. Claude が日本語で説明する**

数字を読んで「6年で20.4%減ですが、生活道路全体は30.5%減なので占める割合は
上がっています」と書く。追い質問（「じゃあ千葉県だけで」）が通じるのは、
claude.ai が会話履歴を保持しているから。こちらは一切関与しない。

所要時間は実測で **1.6〜3秒**。

## 3. いま動いているもの

| | 何 | 状態 |
|---|---|---|
| データ | R2 の `honhyo_2019-2024.parquet` | **恒久**。公開URL・CORS設定済み |
| サーバー | `python mcp_server/server.py --http --port 8765` | このPC上のプロセス |
| トンネル | `cloudflared tunnel --url http://127.0.0.1:8765` | このPC上のプロセス |
| 公開URL | `https://<ランダム>.trycloudflare.com/mcp` | **一時的**。再起動で変わる |
| Claude Code | `claude mcp add` で stdio 登録済み | 恒久。トンネル不要 |
| ビュー | `mcp_server/app/dist/*.html`（ダッシュボード・地図） | ビルド済み。`npm run build` で再生成 |

**Claude Code から使う経路にはトンネルもHTTPも要らない。** stdio でこのPC上の
プロセスと直接やり取りするので、`claude mcp` に登録した時点で完結している。

**claude.ai から使う経路だけがトンネルに依存している。** claude.ai はブラウザ上で
動くので localhost に到達できず、公開HTTPSが要る。

### 起動手順

```bash
# ターミナル1: MCPサーバー
cd npa-traffic-accident-analytics
python mcp_server/server.py --http --port 8765 --allow-host <トンネルのホスト名>

# ターミナル2: トンネル
cloudflared tunnel --url http://127.0.0.1:8765
```

トンネルを先に起動してホスト名を確認し、それをサーバーに渡す。
順番が逆だと Host ヘッダ検証で弾かれる（4-3 参照）。

## 4. なぜこの作りなのか

### 4-1. コード値で受け取る理由

コード表のラベルは**全角ハイフンマイナス（U+FF0D）**と**全角チルダ（U+FF5E）**を使う。
見た目がほぼ同じ別文字を1つ混ぜると、クエリはエラーにならず**0件を返す**。

| 表記 | 結果 |
|---|---:|
| `単路－3.5m未満`（U+FF0D） | 49,739件 |
| `単路-3.5m未満`（ASCIIハイフン） | **0件** |
| `単路ー3.5m未満`（長音符） | **0件** |
| `0〜24歳`（波ダッシュ U+301C） | **0件** |

LLMにラベル文字列を書かせると、この取り違えがいつか起きる。しかも
**間違いが間違いに見えない**。`'01','02','11'` のようなASCIIのコードで受け取り、
サーバー側の辞書でラベルに変換すれば、この事故は構造的に起きない。

`run_sql` は生SQLを受け付けるため例外だが、文字列リテラルを照合して
似た別文字なら正しいラベルに自動修復し、修復内容を `corrections` として返す。
黙って直さない。

### 4-2. 語彙は機械生成する

`mcp_server/vocab.py` は `converter/codes` から生成したもので、手で書いていない。
全角文字を手入力しないためと、もう1つ理由がある。

**1つのコードが複数のラベルを持つ場合がある。** 当事者種別の `36` は
2023年以前が `二輪車－原付自転車`、2024年以降が `二輪車－一般原付自転車`。
片方だけで絞ると年次をまたいで取りこぼす。`vocab.py` は2019〜2024の全年次を
統合しているので、両方が IN 句に入る。

### 4-3. Host ヘッダの許可が要る理由

MCP SDK は DNSリバインディング対策で Host ヘッダを検証し、既定では
localhost しか通さない。トンネルや独自ドメイン越しに公開すると
`Invalid Host header` で弾かれるため、`--allow-host` でホスト名を渡す。

恒久的なホスティングでも同じ対応が必要になる。

### 4-4. 定義をサーバーに持たせる理由

「生活道路」の定義も「年齢は7区分しかない」も、利用者は知らない。
サーバーの `instructions` とツールの説明文に書いておけば、
**利用者のClaudeがそれを読んで正しく使う**。利用者が定義を学ぶ必要がない。

原典は [../CLAUDE.md](../CLAUDE.md)。そこから移植している。

## 5. いまの制約

| | |
|---|---|
| **URLが変わる** | quick tunnel のため、再起動のたびに claude.ai の登録をやり直す |
| **PCが動いている間だけ** | サーバーとトンネルの両方が起動している必要がある |
| **認証がない** | URLを知っていれば誰でも叩ける。データは公開オープンデータなので情報漏洩はないが、このPCの計算資源が使われる |
| **探索はできない** | 提供しているのは集計ツールだけ。データの素性を調べる（列の値を全部見る、文字コードを検証する等）には Claude Code 側のセッションが要る |
| **ビューはターミナルに出ない** | UI付きの2ツールは iframe を持つホスト（Claude Desktop・claude.ai）でだけ描画される。Claude Code では数字だけが返る |
| **地図は全点を描かない** | 既定5,000件・上限20,000件で間引く。全1,895,275件の点表示は既存 viewer + PMTiles の担当 |

## 6. 恒久化するには

| 選択肢 | URL固定 | 常時稼働 | 費用 | 状態 |
|---|---|---|---|---|
| Cloudflare 名前付きトンネル | ○（`shi-works.com` のサブドメイン） | PCに依存 | 無料 | 未着手 |
| 小さなVM（Fly.io / Railway 等） | ○ | ○ | 月数百円〜 | 未着手 |
| Cloudflare Workers Paid + duckdb-wasm | ○ | ○ | $5/月 | **未検証**（メモリ128MBの壁） |

Workers はバンドル64MiB・CPU時間はクリアするが、35.7MBのwasmを読み込んだうえで
DuckDBのヒープを128MB以内に収められるかが分からない。実測が要る。

恒久化の際は認証も併せて決める。
