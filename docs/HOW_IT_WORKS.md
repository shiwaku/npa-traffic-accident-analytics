# 仕組み

いま動いているものが、何をどう処理しているか。
設計の経緯と採らなかった案は [DESIGN.md](DESIGN.md) にある。

---

## 1. 全体像

登場するのは4つだけ。

```
① claude.ai / Claude Code        利用者が日本語で聞く。対話はここが担う
        │  MCP（HTTPS、Claude Code は stdio）
        ▼
② MCPサーバー  mcp_server/server.py     質問の条件 → SQL に組み立てる
        │  DuckDB
        ▼
③ honhyo_2019-2025.parquet（Cloudflare R2）   111.6MB・1ファイル
        │
        ▼
④ 集計結果（＋画面） → ① に返り、Claude が日本語で説明する
```

**対話しているのは①であって、こちらのサーバーではない。**
②は「この条件で集計して」と言われたら数字を返すだけの部品で、会話の文脈も
言葉の解釈も持っていない。ここを取り違えると全体が分からなくなる。

②は2か所で動いている。どちらも同じ `server.py` で、parquet の読み方だけが違う。

| | どこで動くか | parquet の読み方 |
|---|---|---|
| claude.ai から | Cloudflare Containers（Worker が前に立つ） | 起動時に R2 から丸ごと落とし、ローカルディスクから読む |
| 手元の Claude Code から | このPC（stdio） | R2 から httpfs で、必要な列だけ Range リクエストで取る |

読み方を分けた理由は 6-5 に書く。

## 2. 集計：質問1つで何が起きるか

「生活道路の若年層の事故の推移は？」と入力したときの流れ。

**1. 利用者のClaudeが質問を読む**

コネクタを登録した時点で、Claude はサーバーの `instructions`（定義7項目）と
ツールの説明文を受け取っている。そこに「生活道路は交差点の扱いで数え方が2通りあり、
件数が約1.8倍変わる」「年齢は0〜24歳が最小区分」と書いてあるので、曖昧なら聞き返す。

**2. ツールを呼ぶ**

Claude が `aggregate` を呼ぶ。引数はこうなる。

```json
{
  "group_by": ["year"],
  "seikatsu": "strict",
  "party_age": ["01"],
  "party_type": ["61", "51", "52"],
  "party_scope": "either"
}
```

**ラベル文字列ではなくコード値**を渡す。理由は 6-1 に書く。
引数には型があり、ツールに無い引数を渡すとエラーで返す（黙って無視しない）。

**3. サーバーがSQLを組み立てる**

コード値をラベルに変換し、WHERE 句を作る。生活道路の定義（どの車道幅員を含めるか）は
`mcp_server/definitions.py` の1か所にある。

```sql
SELECT "資料年次" AS 年, count(*) AS 件数, ...
FROM honhyo
WHERE "車道幅員" IN ('単路－3.5m未満','単路－3.5m以上','交差点－小（5.5m未満）－小')
  AND (("年齢（当事者A）" IN ('0～24歳') AND "当事者種別（当事者A）" IN ('歩行者','軽車両－自転車','軽車両－駆動補助機付自転車'))
    OR ("年齢（当事者B）" IN ('0～24歳') AND "当事者種別（当事者B）" IN ('歩行者','軽車両－自転車','軽車両－駆動補助機付自転車')))
GROUP BY 1 ORDER BY 1 LIMIT 200
```

年齢と当事者種別は**同じ当事者**で組にして判定する（「Aが若者で、Bが歩行者」のような
別人の属性を混ぜない）。A・B のどちらかが当てはまる事故を、行単位で1件と数える。

`seikatsu_dashboard` は、全事故と生活道路を**1本の SQL で同時に**数える。
母数と分子が同じクエリから出るので、指数を比べてもずれない。

```sql
SELECT "資料年次" AS 年,
       count(*) AS 全事故件数,
       count(*) FILTER (WHERE "車道幅員" IN ('単路－3.5m未満', '単路－3.5m以上', '交差点－小（5.5m未満）－小')) AS 件数,
       ...
FROM honhyo
WHERE "資料年次" >= 2019 AND "資料年次" <= 2025
GROUP BY 1 ORDER BY 1
```

**4. DuckDB が parquet を読む**

Parquet は列指向なので、読まない列は読まれない。座標系の列が全体の約7割を
占めるが、集計では触らない。手元の Claude Code（httpfs）なら、111.6MB のうち
転送されるのは**約5MB**。年を絞れば0.84MBまで下がる。

**5. 結果を返す**

数字に加えて、**実行したSQL**と**注意事項**を返す。画面付きのツールは、画面も返す（4章）。

```json
{
  "rows": [{"年": 2019, "件数": 10335, ...}, ...],
  "notes": [
    "生活道路は車道幅員5.5m未満の道路。…この集計は「5.5m未満の道と、5.5m未満どうしの交差点」で数えた。片方だけ5.5m未満の交差点も数えると、件数は約1.8倍になる",
    "0〜24歳は年齢層コードの最小区分。10代のみ・20代のみの切り出しはできない",
    "当事者AまたはBが条件を満たす事故を行単位で1件と数えた(二重計上なし)"
  ],
  "sql": "SELECT ..."
}
```

`notes` は Claude が利用者に伝えるための材料。どの定義を使ったかを黙って
済ませないための仕掛けでもある。

**6. Claude が日本語で説明する**

数字を読んで「6年で20.4%減ですが、生活道路全体は30.5%減なので占める割合は
上がっています」と書く。追い質問（「じゃあ千葉県だけで」）が通じるのは、
claude.ai が会話履歴を保持しているから。こちらは一切関与しない。

所要時間は実測で **1.6〜3秒**。

## 3. 地図：半径で切って、点を返す

「新宿駅から半径1kmで、若い歩行者・自転車が関わった7年分の事故を地図に」の流れ。
2章と違うところだけ書く。

**1. Claude が中心座標を決めて `accident_map` を呼ぶ**

```json
{
  "seikatsu": "strict",
  "party_age": ["01"],
  "party_type": ["61", "51", "52"],
  "center_lat": 35.6896, "center_lon": 139.7006, "radius_m": 1000
}
```

**サーバーは地名から座標を引けない。** 「新宿駅」の座標は Claude が推測している。
推測がずれると件数も変わる（#67）。Android の claude.ai アプリは、端末の位置情報から
現在地の座標を Claude に渡せる。

**2. 半径は、緯度・経度の列だけで切る**

`geometry` 列も DuckDB の spatial 拡張も使わない（`honhyo` ビューは geometry を外している）。
まず緯度・経度の範囲（四角）で粗く絞り、残った行だけ距離を計算して円で切る。
経度1度あたりの距離は、中心の緯度の cos で縮める。

```sql
AND lat BETWEEN 35.68055350 AND 35.69864650
AND lon BETWEEN 139.68953963 AND 139.71166037
AND ((lon - 139.7006) * 111320.0 * cos(35.6896°))² + ((lat - 35.6896) * 110540.0)² <= 1000²
```

半径1km程度なら、この平面近似で誤差は問題にならない。座標は0.1秒（緯度で約3m）刻みで
記録されているので、半径50m程度の指定にも耐える。

**3. 点は配列で軽く返す**

GeoJSON ではなく、1件を数字の配列にし、文字列の項目は凡例の番号にして返す。

```json
{
  "fields": ["lon", "lat", "年", "死亡", "事故類型", "種別A", "種別B", "車道幅員", "昼夜", "ゾーン30", "都道府県"],
  "points": [[139.70018, 35.69335, 2024, 0, 2, 8, 9, 2, 0, 0, 0], ...],
  "legend": {"事故類型": ["人対車両", "車両相互", "車両単独"], ...},
  "counts": {"該当": 36, "描画": 36}
}
```

点が `max_points`（既定5,000・上限20,000）を超えると間引いて描く。間引きは
`hash(lon, lat, 年, …)` の順なので、同じ条件なら同じ点が出る。
**件数は間引く前の `counts.該当` で伝える**（描画件数は事故件数ではない）。

## 4. 画面：ツールが表示用の HTML も返す（MCP Apps）

MCP サーバーだけなら、返るのは数字で、Claude がそれを文章にする。
MCP Apps はその拡張で、ツールが画面も一緒に返し、グラフや地図が会話の中に出る。

**1. ツールに画面を結び付ける**

```python
@apps.tool(
    resource_uri="ui://npa-traffic-accident/accident-map.html",
    visibility=["model", "app"],   # Claude からも、画面からも呼べる
)
def accident_map_tool(...): ...
```

画面は `mcp_server/app/` の TypeScript を Vite で単一 HTML にまとめたもの
（地図は MapLibre GL ごと入っている）。`npm run build` で `dist/` に出る。
ダッシュボード・地図・集計表の3つがある。

**2. ホストが iframe で開き、結果を渡す**

claude.ai などのホストが、その HTML を sandbox の iframe に読み込み、
ツールの結果を postMessage で渡す。画面側は `app.ontoolresult` で受け取って描く。
iframe を持たないホスト（ターミナルの Claude Code）では画面は出ず、数字だけが返る。
集計としては壊れない。

**3. 外へ通信できるのは、宣言した先だけ**

iframe はホストの CSP で外部通信を止められている。地図の画面だけは、
背景の地理院 最適化ベクトルタイル（淡色）を読むために、リソースの `_meta.ui.csp` で
`cyberjapandata.gsi.go.jp` と `gsi-cyberjapan.github.io` を宣言している（`mcp_server/accident_map.py`）。
「現在地」ボタンのために位置情報の利用も要求しているが、許すかどうかはホスト次第。

**4. 画面のボタンは、Claude を通さずにツールを呼び直す**

「死亡事故のみ」や生活道路の数え方の切り替えは、画面から
`app.callServerTool({ name: "accident_map", arguments: {...前回の条件, fatal_only: true} })`
でサーバーを直接呼ぶ。前回の条件（中心座標・半径を含む）を引き継いで、変えた項目だけ差し替える。

## 5. いま動いているもの

| | 何 | 状態 |
|---|---|---|
| データ | R2 の `honhyo_2019-2025.parquet` | **恒久**。公開URL・CORS設定済み |
| サーバー（claude.ai 用） | Cloudflare Workers + Containers（`deploy/cloudflare/`） | **稼働中**。basic（1/4 vCPU・1 GiB）、コンテナは1台 |
| 入口 | Worker の `/s/<SECRET_PATH>/mcp`（自分用）、`/e/<EVENT_PATH>/mcp`（発表会の来場者用、期限で自動停止） | それ以外のパスは 404 |
| Claude Code | `claude mcp add` で stdio 登録済み | 恒久。このPC上でサーバーが動く |
| ビュー | `mcp_server/app/dist/*.html`（ダッシュボード・地図・集計表） | ビルド済み。`npm run build` で再生成 |

デプロイ・課金・スリープの詳細は [deploy/cloudflare/README.md](../deploy/cloudflare/README.md)。

**Claude Code から使う経路にはネットワーク上のサーバーが要らない。** stdio でこのPC上の
プロセスと直接やり取りするので、`claude mcp` に登録した時点で完結している。

**claude.ai から使う経路には公開 HTTPS が要る。** claude.ai はブラウザ上で動くので
localhost に到達できない。そのため Cloudflare に置いている。

### 手元で HTTP サーバーを試すとき

Cloudflare に上げる前の確認は、手元で HTTP サーバーを立ててトンネルで公開する。

```bash
# ターミナル1: MCPサーバー
cd npa-traffic-accident-analytics
python mcp_server/server.py --http --port 8765 --allow-host <トンネルのホスト名>

# ターミナル2: トンネル
cloudflared tunnel --url http://127.0.0.1:8765
```

トンネルを先に起動してホスト名を確認し、それをサーバーに渡す。
順番が逆だと Host ヘッダ検証で弾かれる（6-3 参照）。quick tunnel の URL は再起動のたびに変わる。

## 6. なぜこの作りなのか

### 6-1. コード値で受け取る理由

コード表のラベルは**全角ハイフンマイナス（U+FF0D）**と**全角チルダ（U+FF5E）**を使う。
見た目がほぼ同じ別文字を1つ混ぜると、クエリはエラーにならず**0件を返す**。

| 表記 | 結果（全期間） |
|---|---:|
| `単路－3.5m未満`（U+FF0D） | 55,520件 |
| `単路-3.5m未満`（ASCIIハイフン） | **0件** |
| `単路ー3.5m未満`（長音符） | **0件** |
| `0〜24歳`（波ダッシュ U+301C） | **0件** |

LLMにラベル文字列を書かせると、この取り違えがいつか起きる。しかも
**間違いが間違いに見えない**。`'01','02','11'` のようなASCIIのコードで受け取り、
サーバー側の辞書でラベルに変換すれば、この事故は構造的に起きない。

`run_sql` は生SQLを受け付けるため例外だが、文字列リテラルを照合して
似た別文字なら正しいラベルに自動修復し、修復内容を `corrections` として返す。
黙って直さない。

### 6-2. 語彙は機械生成する

`mcp_server/vocab.py` は `converter/codes` から生成したもので、手で書いていない。
全角文字を手入力しないためと、もう1つ理由がある。

**1つのコードが複数のラベルを持つ場合がある。** 当事者種別の `36` は
2023年以前が `二輪車－原付自転車`、2024年以降が `二輪車－一般原付自転車`。
片方だけで絞ると年次をまたいで取りこぼす。`vocab.py` は2019〜2024の全年次（2025年はコード値の追加なし）を
統合しているので、両方が IN 句に入る。

### 6-3. Host ヘッダの許可が要る理由

MCP SDK は DNSリバインディング対策で Host ヘッダを検証し、既定では
localhost しか通さない。トンネルや独自ドメイン越しに公開すると
`Invalid Host header` で弾かれるため、`--allow-host` でホスト名を渡す。

### 6-4. 定義をサーバーに持たせる理由

「生活道路」の定義も「年齢は8区分しかない」も、利用者は知らない。
サーバーの `instructions` とツールの説明文に書いておけば、
**利用者のClaudeがそれを読んで正しく使う**。利用者が定義を学ぶ必要がない。

原典は [../CLAUDE.md](../CLAUDE.md)。そこから移植している。

### 6-5. クラウドでは parquet を丸ごと落とす理由

httpfs は1クエリを数十〜数百の Range リクエストに分ける。コンテナで CPU を絞ると、
この往復が効いてダッシュボードの集計に53秒かかった。同じ parquet をローカルディスクから
読むと、1/4 vCPU でも約1秒。そこで起動時に111.6MBを1回落とす（`deploy/cloudflare/entrypoint.py`、
実機で約7.5秒）。コンテナは寝るとディスクも消えるので、起きるたびに落とし直す。

手元の Claude Code は回線と CPU に余裕があるので、httpfs のまま（全7年の集計で3.35秒）。

## 7. いまの制約

| | |
|---|---|
| **認証は秘密URLだけ** | URLを知っていれば誰でも叩ける。データは公開オープンデータなので情報漏洩はないが、コンテナの計算資源が使われる |
| **コンテナは1台** | 同時に大勢が使うと遅くなる。40人同時の負荷試験の結果は [deploy/cloudflare/README.md](../deploy/cloudflare/README.md) |
| **地名から座標を引けない** | 駅名・住所の座標は Claude の推測に頼っている（#67） |
| **ビューはターミナルに出ない** | UI付きのツールは iframe を持つホスト（Claude Desktop・claude.ai）でだけ描画される。Claude Code では数字だけが返る |
| **地図は全点を描かない** | 既定5,000件・上限20,000件で間引く。全2,182,298件の点表示は既存 viewer + PMTiles の担当 |
