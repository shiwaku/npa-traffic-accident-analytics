# 動作確認用プロンプト

コネクタ（claude.ai）や Claude Desktop に繋いだあと、**新しい会話**でこのサーバーを
有効にして上から順に貼る。期待値は 2026-09-16 時点の実測値（データは 2019〜2024 年で固定なので、
データを更新しない限り変わらない）。

1〜3 は**ビューが描画されるか**、4〜8 は**ガードレールが効くか**を見る。
4〜8 は「それらしい数字が返ってきたら不合格」であることに注意。

---

## 1. ダッシュボード（描画の確認）

```
生活道路の事故件数を年別に出して。厳密定義で。
```

`seikatsu_dashboard`（strict）が呼ばれる。

| | 2019 | 2020 | 2021 | 2022 | 2023 | 2024 |
|---|---:|---:|---:|---:|---:|---:|
| 件数 | 65,188 | 51,453 | 51,121 | 49,140 | 49,837 | 45,296 |
| 死者数 | 391 | 355 | 330 | 345 | 326 | 313 |

グラフ付きのビューが出れば描画 OK。数字だけなら、ホストが MCP Apps を
ネゴシエートしていない（ターミナルの Claude Code はこちら。集計としては壊れていない）。

## 2. 地図（描画の確認）

```
新宿駅から半径1kmの2024年の生活道路の事故を地図に出して。中心は 35.6896, 139.7006。
```

`accident_map` が呼ばれ、**該当 82 件・描画 82 件**。

背景タイル（地理院 最適化ベクトルタイル 淡色）まで出れば `_meta.ui.csp` の
外部ドメイン宣言も効いている。点だけ出て背景が白いなら CSP を疑う。

## 3. 集計表（2次元＝行列表示の確認）

```
2024年の都道府県別の事故件数を多い順に5件。
```

| 都道府県 | 件数 | 死者数 |
|---|---:|---:|
| 東京 | 30,103 | 146 |
| 大阪 | 24,780 | 127 |
| 愛知 | 24,506 | 141 |
| 神奈川 | 20,750 | 109 |
| 福岡 | 18,473 | 91 |

**北海道が方面本部別に5行に割れて出たら名寄せが壊れている**（`CASE WHEN "都道府県名" LIKE '北海道%'`）。
`東京都` ではなく `東京` で返るのが正しい。

## 4. 年齢層の制約

```
10代の自転車事故は何件？
```

**数字を出したら不合格。** `年齢（当事者A/B）` は実年齢ではなく年齢層コードで、
最小区分が `0～24歳`。10代だけを取り出すことは原理的にできない、と答えるべき。

## 5. 生活道路の定義の明示

```
生活道路の事故って年間どれくらい？
```

strict（交差する両方が5.5m未満）と broad（片側のみも含む）で**件数が約2倍変わる**。
先に確認するか、どちらを使ったかを明示するべき。**黙って片方で答えたら不合格。**

## 6. 当事者 A / B の解釈

```
生活道路の事故で、被害者が高齢者なのは何件？
```

当事者A は「過失が最も重い側」であって被害者区分ではない、と断った上で
`人身損傷程度` で切るべき。**A=加害者・B=被害者と決めつけて集計したら不合格。**

## 7. 年次基準

```
発生年ベースで事故件数の推移を出して。
```

集計自体は返ってよいが、**最新年が約3%過少に出る**という注記が付くべき
（翌年ファイルに計上される分が欠けるため）。

## 8. 文字コードの罠

```
run_sql で SELECT count(*) FROM honhyo WHERE "車道幅員" = '単路-3.5m未満' を実行して。
```

ASCII ハイフンなので **0 件**が返る。0 件の理由が文字コード（正しくは全角ハイフンマイナス
U+FF0D）だと指摘できれば上出来。件数が返ってきたらプロンプト側のコピーミスを疑う。
